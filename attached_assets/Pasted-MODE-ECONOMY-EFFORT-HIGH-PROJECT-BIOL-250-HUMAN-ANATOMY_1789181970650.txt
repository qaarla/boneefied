======================================================================
PRODUCT MODEL
======================================================================

This is not primarily a flashcard app.

It is an IMAGE-FIRST ANATOMY LAB-PRACTICAL STUDY APP.

The course source material includes:

- anatomical models
- labeled and unlabeled diagrams
- numbered and lettered structures
- histology images
- neuron/cell diagrams
- bones and landmarks
- muscles
- organs
- pathways
- cranial and peripheral nerves
- course quiz questions
- lab review material
- practical-style image questions

The mobile UI must be designed around recognizing structures visually.

======================================================================
PRIMARY MOBILE NAVIGATION
======================================================================

Use four bottom tabs:

1. STUDY
2. PRACTICE
3. MISSED
4. PROGRESS

Keep the navigation simple.

Do not add social features, accounts, authentication, backend services, payments, cloud sync, or other infrastructure in this version.

The app should function offline after installation.

Use the existing project-wide typography direction if present.
If no typography system exists, use Tinos as the app serif and keep the UI clean, readable, compact, and appropriate for dense academic material.

======================================================================
STUDY TAB
======================================================================

The Study tab is also the main landing experience.

Organize content primarily by the actual course labs/modules represented in the source material.

Do not invent lab numbering.

Each module card should show:

- lab/module number when supplied
- title
- progress/mastery
- number of verified study items
- number of exam-priority items if known

Inside a module provide:

LEARN
- labeled image or model
- structure names
- concise source-supported information
- optional function/location/relationship where supplied
- source reference

RECALL
- same material with labels hidden
- tap or reveal individual answers
- reveal-all control

Do not force users through long text before seeing the anatomy image.

======================================================================
PRACTICE TAB
======================================================================

The architecture must support these question types:

- image identification
- hotspot / tap-the-structure
- letter or number identification
- multiple choice
- select-all-that-apply
- typed recall
- matching
- ordered sequence/pathway
- bone laterality
- muscle action
- muscle origin/insertion
- function/relationship
- histology identification

Not every type must be populated during this first pass, but the data model must support them cleanly.

Practice session controls should eventually support:

- module selection
- exam-priority-only toggle
- question type
- question count
- missed/weak material emphasis

======================================================================
MISSED TAB
======================================================================

Every incorrect answer should be capable of entering a persistent missed-item queue.

The student must be able to:

- review missed structures
- retry them
- see the correct answer after committing an answer
- clear an item through later successful recall
- filter by module

Do not destroy the historical attempt record simply because an item is later answered correctly.

======================================================================
PROGRESS TAB
======================================================================

Track progress at STRUCTURE level, not only module level.

Use simple deterministic states:

- New
- Learning
- Needs Review
- Strong
- Mastered

Do not invent a complicated spaced-repetition algorithm in this first pass.

Track:

- attempts
- correct answers
- incorrect answers
- recent performance
- mastery state
- module progress

======================================================================
ANATOMY CONTENT SCHEMA
======================================================================

Create a strongly typed model equivalent to the following concepts.

Exact implementation may differ if there is a cleaner TypeScript design, but all information below must remain representable.

SOURCE

- id
- filename
- hash
- pageCount
- title
- course/lab association
- source type
- attribution/license status
- notes
- verification status

MODULE

- id
- lab number when supplied
- title
- ordering
- source IDs
- visible/published status

STRUCTURE

- id
- canonical name
- accepted aliases
- module ID
- structure category
- source reference
- source page
- examPriority
- verificationStatus

ASSET

- id
- source ID
- source page
- local asset path
- asset type:
  - diagram
  - model
  - histology
  - cadaver
  - syndaver
  - gross specimen
  - worksheet
- labeled/unlabeled status
- attribution/license
- verificationStatus

QUESTION

- id
- module ID
- structure ID or related structure IDs
- task type
- prompt
- asset ID when applicable
- answer
- accepted aliases
- distractors/options when applicable
- explanation when source-supported
- source ID
- source page
- examPriority
- verificationStatus

HOTSPOT

Store hotspot positions as normalized coordinates, not device pixels:

- x from 0 to 1
- y from 0 to 1
- radius relative to image size

This is required so hotspots remain aligned when images resize on different devices.

Additional useful fields:

- anatomical view
- laterality required
- orientation
- specimen type

======================================================================
ANSWER HANDLING
======================================================================

Typed-answer normalization may ignore:

- capitalization
- extra surrounding whitespace
- ordinary punctuation differences

Do not broadly fuzzy-match anatomy words.

Accepted alternate terms must be explicitly stored in acceptedAliases.

Example principle:

If the course explicitly treats two terms as equivalents, both may be accepted.

Do not invent aliases merely because two terms seem similar.
